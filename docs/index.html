talus-process-monitor

Behavioral ransomware detection and response for Linux. Current stable release: v0.8.3 (2026-10-01). Available from PyPI, as a container image and as release binaries.

From PyPI

Python package ships the monitor binary and bindings. Requires a Linux host with eBPF support (kernel 5.8+ recommended).

pip install talus-process-monitor

Container image

Public image on GitHub Container Registry:

docker pull ghcr.io/hartwell-labs/talus-process-monitor:latest

Run flags, mount requirements and tuning (event thresholds, pause/kill response actions) are documented in the repository README and the Field Guide.

CLI reference (essentials)

All flags live in talus --help. Since v0.8.3 monitor flags are also accepted at the top level — both forms below are equivalent:

sudo talus --web 10.0.0.5:8443 --alert-threshold 40
sudo talus monitor --web 10.0.0.5:8443 --alert-threshold 40
FlagWhat it does
--web ADDRDashboard + REST API + WebSocket over TLS (self-signed embedded cert by default)
--httpPlain HTTP for the dashboard (local/lab use only)
--auto-killResponse mode: SIGKILL on verdict (Enterprise)
--alert-threshold NOpens/s per process that fires the verdict (0 disables; signed tuning profile wins when installed)
--canary PATHArm a decoy path; any read is an immediate sev-2 alert, zero false positives by construction
--sweepCANARY + MASS_DELETE + EXFIL_SPIKE detectors (CI edition)
--siem-sink SPECForward events: rfc5424|cef|json@tcp://host:port (repeatable)
--diagnose5-second end-to-end self-diagnostic, prints PASS/FAIL per subsystem

Dashboard & API

With --web the agent serves a triage-first dashboard, a REST API and a WebSocket event stream on https://ADDR (rustls, embedded self-signed certificate — trust it once in the browser, or pass --tls-cert/--tls-key).

# verify the agent is healthy and licensed
curl -k https://10.0.0.5:8443/api/v1/stats | jq .
# fields: events total, events/s, uptime, agent coverage, security posture

The dashboard shows a 5-second answer to "is anything wrong right now?": CRITICAL banner when alerts are open, events/s, agent coverage and an overall SECURITY POSTURE indicator — before you read a single event row. Event noise is aggregated client- and server-side (per-file open bursts collapse into a rate badge, max 200 live rows).

Tuning & detectors

Thresholds are signed into tuning profiles (talus tuning ...) so the fleet policy is verifiable, not tribal knowledge. Deployment-class presets (--sector healthcare|energy|water|government|...) set conservative detector defaults per vertical; explicit flags always win over presets.

  • Canary — decoy paths; reads are alerts by construction, no tuning needed.
  • Mass-delete — ransomware-style unlink bursts outside known installers.
  • Exfil spike — loud per-process egress; pair with SIEM sinks for forensics.
  • Slow-drip — hourly windows for drip/whale/crescendo exfiltration patterns.

Licensing

The detection engine is MIT. The response path, dashboard and SIEM/Kafka/ClickHouse/MemGraph sinks require an Enterprise key ($50/node/year, checkout or request a quote by email). Air-gapped environments activate fully offline:

# air-gap activation (3 steps, zero network on the target)
talus license challenge --out challenge.json   # 1. machine-bound challenge
#   2. send challenge.json to the license owner (offline media)
talus license import-response --file response.json  # 3. owner-signed response activates

License audit log integrity: talus license verify-audit (hash-chained).

Engineering standards

These gates apply across the organization. They are enforced by CI, not by convention:

  • Tests and CI on every push — a feature that doesn't ship with CI doesn't ship.
  • CodeQL static analysis on all active repositories.
  • Continuous fuzzing on talus' eBPF pipeline.
  • Signed releases with provenance — Sigstore-style attestation on release assets.
  • SBOM (SPDX) attached to every talus release.

Supply-chain posture

The flagship repository runs OpenSSF Scorecard and SLSA-style provenance continuously. Release assets are verifiable end-to-end: from source commit, through the build workflow, to the published binary and its attestation file.
